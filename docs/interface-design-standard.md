# 接口设计规范

接口服务于学习、阅读与正确使用。先确认真实调用方式，再决定如何迁移或演进。最小用法应能按同一入口逐步增加能力。

## 保留调用与行为

以原模块的构造方式、常用方法、参数方向、配置形状、默认值、回调和可观察行为建立迁移对照。对照同时覆盖历史用法和当前消费者。兼容别名有实际迁移价值时可以保留，例如 `careatEditor`。

- 编辑器的基础用法从 `new SimpleEditor(element, options)` 开始，使用 `execCommand(cmd, value)`、`getValue(index)` 和 `setValue(value, index)` 管理内容。
- Web Component 的注册入口为 `defineEditorElement()`。元素属性和方法映射到同一编辑器实例。核心编辑操作和变化语义由编辑器包所有。
- 图表的基础用法沿用 `new Charts(element, theme, options)` 和 `setOption(options)`。主题、坐标轴、系列配置、图层和提示交互按真实行为对照。对比范围包括横向区间柱、按轴提示及有需要的图层调用。
- 改变参数解释、默认值、回调时机、更新行为或支持范围时，记录旧用法、当前写法和验证依据。正式示例使用能运行的当前接口。

## 缺省、复用与代指

| 方式 | 规则 | 本项目例子 |
| --- | --- | --- |
| 缺省 | 已有稳定默认时允许省略，说明默认值及覆盖关系 | 编辑区域默认索引、图表主题与实例选项 |
| 复用 | 便利入口调用同一实现，尽量保持输入和结果语义 | 编辑器工厂与构造器、自定义元素与编辑器 |
| 代指 | 通过稳定标识引用已绑定定义，由所属模块解析 | 编辑命令名、图表系列类型、命名主题 |

封装应减少有意义的重复或把必要步骤聚在一起，例如保存并恢复所属编辑区的选区。能直接读懂的单次 DOM 调用保持原生写法。评估简化时看调用者要理解多少概念、决定多少选项，以及同一行为是否还能表达。文件数和行数只作辅助。

## 实例、事件和副作用

实例持有自己的容器、选区、图层和监听。调用者能够知道何时可以操作、何时收到结果、如何释放资源。Web Component 文档明确 `editor-ready`、`editor-change` 及断开重连行为。编辑器和图表的主动释放以 `destroy()` 为入口，事件的来源、数据形状及触发条件由对应契约说明。

区分省略、显式空值和空数组。图表更新未提供的选项继续使用现有值，提供 `series: []` 表示清空系列。接口的 TypeScript 类型、运行时处理和示例同步核对，尤其是浏览器输入、上传回调和调用后可能改变的 DOM。

公开包从清单中的入口消费。内部实现路径只有在承担持续的对外用法时才进入 `exports`。新增公开入口时说明真实消费者及维护职责。
