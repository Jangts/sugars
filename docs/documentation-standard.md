# 文档规范

正式文档为读者说明当前可使用的产品、设计、接口和操作。背景、讨论结论与验证记录各有维护入口。

## 正式文档

- 根 README 提供仓库定位、构建方式和最小用法。项目文档索引提供规范与维护入口。
- 使用说明从公开入口开始，交代运行前提、输入、结果、默认值及生命周期。复杂用法沿用同一入口扩展示例。
- 实现限制按真实行为说明。计划和待核对的问题写入维护资料。正式文档的签名、示例和链接与当前源码或对应发布版本一致。
- 同一事实由一篇责任文档维护。其他文档提供链接和必要上下文。

## 维护资料

背景、迁移对照、调查、计划及验收证据归入 `docs/maintenance/`，在索引中写明用途。记录区分已确认的决定、已经实现的行为、实际运行过的检查和未覆盖范围。原件与外部参考保留来源，迁移副本标明到模块的对应关系。

## 接口和文档同步

修改导出、参数、默认值、事件、行为或素材时，同步责任文档、公开示例和相应发布文件。生成内容通过更改来源更新。审校选择与改动相符的范围，例如相对链接、公开签名、调用结果或实际包体。

## 公开包说明

实际发布前从新使用者的角度检查各包的 README 与 npm 元数据。说明浏览器前提、安装命令、完整 import、最小可运行用法及清理方式。Web Component 说明其编辑器依赖和元素注册时机。真实 tarball 中应包含相应说明、运行文件、类型和实际消费的素材。相对链接应有随包或公开可访问的目标。

发布访问级别、打包预检和 registry 中已存在的版本是三个不同事实，分别记录。素材和代码许可按各自的来源处理，保留适用声明。只有实际验证过的发布和使用结果才记为通过。
